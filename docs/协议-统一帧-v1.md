# 统一帧协议 v1

> **一份协议，服务所有链路。**
> 制定：2026-11-27　状态：**草案（待实现）**
> 本文档是"合同"：PC 侧、STM32 侧、CPU 侧的实现都必须照此对照。

---

## 1. 为什么需要它

现在项目里有 **5 条链路、4 种格式**：

| 链路 | 现在的格式 | 问题 |
| --- | --- | --- |
| PC → FPGA（装载） | 裸字节 + `0xFF` 终止 | **程序里不能有 0xFF**；串口打开瞬间的杂散字节会错位 |
| FPGA → STM32（角度） | 单字节 | 噪声 → 舵机乱跳 |
| STM32 → FPGA（距离） | 单字节 | 噪声 → 角度乱跳 |
| STM32 → PC（雷达） | 文本 `a=90 d=123\r\n` | 和 ① 的二进制帧**并存** |
| STM32 → PC（① 协议） | `AA 55 LEN CMD SEQ PAYLOAD CRC8` | 未启用，但已有 68 条单测 |

**目标：统一成一套帧格式，一套封包/解包代码，一份文档。**

---

## 2. 帧格式

```
┌───────┬──────┬─────┬──────────────┬─────┐
│ AA 55 │ TYPE │ LEN │ PAYLOAD[LEN] │ CHK │
│  2B   │  1B  │ 1B  │     LEN B    │ 1B  │
└───────┴──────┴─────┴──────────────┴─────┘
固定开销：5 字节
整帧长度 = LEN + 5
```

| 字段 | 宽度 | 值域 | 说明 |
| --- | ---: | --- | --- |
| `AA 55` | 2B | 固定 | 帧头（**双字节**，自动同步） |
| `TYPE` | 1B | 见 §3 | 帧类型 |
| `LEN` | 1B | 0~250 | **PAYLOAD 的字节数**（不含帧头/TYPE/LEN/CHK） |
| `PAYLOAD` | LEN | — | 类型相关，多字节字段**小端** |
| `CHK` | 1B | — | 校验（见 §4） |

### 为什么帧头是 `AA 55`

| 理由 | 说明 |
| --- | --- |
| **误同步率低** | 随机数据连续命中 `AA` 再 `55` 的概率 ≈ 1/65536；128 字节帧内约 0.2%，再经 LEN/CHK 过滤 ≈ 0 |
| **反码对可查极性** | `AA`=1010_1010，`55`=0101_0101 互为反码；线路一旦反相，`AA 55` 变 `55 AA`，一眼可见 |
| **既有资产** | ① 的 `protocol.cpp` 已有 68 条单测围绕它，更换等于全废 |
| **视觉醒目** | hex dump 里最容易被人眼识别 |

> **它不是魔法**：`0x7E`（PPP）、`0x55AA` 都能用。选 `AA 55` 是"惯例 + 既有资产"的折中。

---

## 3. TYPE 分配

| TYPE | 方向 | 名称 | PAYLOAD | 说明 |
| --- | --- | --- | --- | --- |
| `0x01` | PC → CPU | **LOAD** | `ADDR(1) + DATA(N)` | 把 DATA 依次写入 `ADDR, ADDR+1, …`；**不执行** |
| `0x02` | CPU → STM32 | **SET_ANGLE** | `ANGLE(1)` | 0~180，超出钳位 |
| `0x03` | STM32 → CPU | **DIST** | `DIST(1)` | 0~250 cm；**≥251 保留为错误码** |
| `0x04` | 任意 | **ESTOP** | 空（LEN=0） | 急停 |
| `0x05` | PC → CPU | **RUN** | `ADDR(1)` | `PC = mem[ADDR]`，开始执行 |
| `0x06` | PC → CPU | **PING** | 空 | CPU 回 `OUT 0xA5`（链路自测） |
| `0x10` | STM32 → PC | **STATUS** | `ANGLE(1) + DIST_LO(1) + DIST_HI(1) + ERR(1)` | 状态上报；DIST 小端 |

### 为什么装载和运行要分开

| 旧做法 | 新做法 |
| --- | --- |
| `0xFF` 终止符一到就 `JMPX` 执行 | **LOAD 只写内存，RUN 才执行** |

好处：
- 可以**分段装载**（长程序分多帧）
- **装载地址灵活**（不再固定 0x80）
- **程序里可以出现 0xFF**（LEN 决定长度，不靠终止符）
- 装载完成后可以先回读校验，再 RUN

## 4. 校验算法（累加和）

```text
CHK = (TYPE + LEN + PAYLOAD[0] + PAYLOAD[1] + … + PAYLOAD[LEN-1]) & 0xFF
```

**覆盖范围：从 TYPE 到 PAYLOAD 末尾**（不含帧头 `AA 55`）。

### 为什么是累加和，不是 XOR / CRC

| 算法 | 8 位 CPU 成本 | 检错能力 |
| --- | --- | --- |
| **累加和** | `ADD chk` + `STA chk` = **2 条指令/字节** | 单字节错、多数字节错可查 |
| XOR | **做不到**（ISA 没有 XOR 指令） | — |
| CRC8 | 约 20 条指令/字节（无移位指令，要用 `ADD` 模拟 ×2） | 最强 |

**在 20cm 杜邦线上，累加和足够。CRC8 留给 PC 侧的 ① 协议（那边有 FPU 和库）。**

### 参考实现（Python）

```python
def frame(typ: int, payload: bytes) -> bytes:
    chk = (typ + len(payload) + sum(payload)) & 0xFF
    return bytes([0xAA, 0x55, typ, len(payload)]) + payload + bytes([chk])
```

### 参考实现（C）

```c
uint8_t chk = type + len;
for (uint8_t i = 0; i < len; i++) chk += payload[i];
```

## 5. 实例帧（校验值已实测）

| 场景 | 帧（hex） |
| --- | --- |
| **PING** | `AA 55 06 00 06` |
| **ESTOP** | `AA 55 04 00 04` |
| **SET_ANGLE 90°** | `AA 55 02 01 5A 5D` |
| **DIST 40cm** | `AA 55 03 01 28 2C` |
| **RUN 从 0x80** | `AA 55 05 01 80 86` |
| **LOAD 到 0x80，5 字节**（`LDI 42; OUT; HLT; 0xFF`） | `AA 55 01 06 80 05 2A 08 0F FF CC` |
| **STATUS**（90° / 100cm / err=0） | `AA 55 10 04 5A 64 00 00 D2` |

> **LOAD 那帧特别注意**：数据里含 `0xFF`，**旧协议（终止符 `0xFF`）根本发不出去**——这就是新协议最直接的收益。

## 6. 接收方状态机

```text
        ┌─────────────────────────────────────────┐
        │  S_HUNT   （找帧头）                      │
        │  byte != 0xAA → 留在 S_HUNT               │
        │  byte == 0xAA → S_HUNT2                   │
        └───────────────┬─────────────────────────┘
                        ▼
        ┌─────────────────────────────────────────┐
        │  S_HUNT2                                │
        │  byte == 0x55 → S_TYPE（chk = 0）        │
        │  else        → 回 S_HUNT                 │
        └───────────────┬─────────────────────────┘
                        ▼
        ┌─────────────────────────────────────────┐
        │  S_TYPE  → 读 TYPE，chk += TYPE          │
        │  S_LEN   → 读 LEN，chk += LEN；LEN>250 → 丢 │
        │  S_DATA  → 读 LEN 个字节，chk += byte    │
        │  S_CHK   → 读 CHK；比较 → 有效 / 丢弃    │
        └─────────────────────────────────────────┘
```

### 超时与重同步

| 规则 | 值 | 理由 |
| --- | --- | --- |
| **帧内字节间隔超时** | **50 ms** | 115200 下一字节 87 µs，留 500 倍余量；超时回 `S_HUNT` |
| 校验失败 | 丢弃整帧，回 `S_HUNT` | 不做重传（上层负责重发） |
| LEN > 250 | 立即丢帧 | 防缓冲区溢出 |
| 收到帧头时 | `chk` 清零，重开一帧 | — |

> **超时在 CPU 上怎么实现**：monitor 没有定时器，用**计数循环**近似（例如每收一字节前先跑 N 次空转，超过就放弃）。这是 CPU 侧实现的一个待定细节。

## 7. 各链路映射（最终形态）

```text
PC ──LOAD/PING/RUN(01/06/05)──▶ FPGA ──SET_ANGLE(02)──▶ STM32
                                  ▲                        │
                                  └──── DIST(03) ──────────┘
                                                           │
PC ◀──────────── STATUS(10) ──────────────────────────────┘
```

| 链路 | 用哪些 TYPE | 谁来解析 |
| --- | --- | --- |
| PC → FPGA | `01` LOAD / `05` RUN / `06` PING | **monitor（CPU 软件）** |
| FPGA → STM32 | `02` SET_ANGLE / `04` ESTOP | STM32（中断里解析） |
| STM32 → FPGA | `03` DIST | **CPU 软件** |
| STM32 → PC | `10` STATUS | PC（radar.py / Qt） |

> **不再有裸字节链路**（除了 STM32 的调试口，见 §9）。

## 8. CPU 侧实现成本

### monitor（装载器）需要多少代码

| 功能 | 估算字节 |
| --- | ---: |
| 找帧头 `AA 55` | 10 |
| 读 TYPE / LEN | 8 |
| 循环收 PAYLOAD + 累加校验 | 25 |
| 读 CHK 并比较 | 8 |
| LOAD 分支（`STX` 间接写） | 12 |
| RUN 分支（`JMPX`） | 6 |
| PING 分支（`OUT 0xA5`） | 6 |
| 错误/重同步 | 10 |
| **合计** | **约 85 字节** |

对比现在 monitor 的 29 字节 → **约 3 倍**，但仍然放得下。

### 内存布局（建议）

| 地址 | 用途 |
| --- | --- |
| `0x00~0x6F` | monitor 代码 |
| `0x70~0x7F` | monitor 变量（state / len / addr / chk / idx） |
| `0x80~0xFE` | **装载区（127 字节）** |
| `0xFF` | 保留 |

**因此：单帧 LOAD 最大 LEN = 126**（1 字节 ADDR + 126 字节数据）。

### 时序预算

| 项 | 值 |
| --- | --- |
| 串口一字节 | 87 µs |
| CPU 处理一字节 | 约 15 拍 = **0.55 µs** |
| 余量 | **约 150 倍** ✅ |

## 9. 与旧格式的关系

| 旧 | 新 | 处理 |
| --- | --- | --- |
| L1 裸字节 + `0xFF` 终止 | LOAD + RUN 帧 | **替换**（monitor 重写） |
| L3 单字节距离 | DIST 帧 | **替换** |
| L4 文本行 `a=90 d=123` | STATUS 帧 | **保留文本作调试模式**，但加前缀 `#`，PC 端可过滤 |
| L5 `AA 55 LEN CMD SEQ PAYLOAD CRC8` | 本协议 | **字段简化**（去 SEQ，CHK 从 CRC8 降为累加和）；68 条单测需同步调整 |

> **注意**：L5 的 CRC8 降到累加和，是"为 8 位 CPU 让路"。
> PC ↔ STM32 之间其实可以继续用 CRC8（两边都有算力）——**待决策**：是否允许"PC 侧用 CRC8、CPU 侧用累加和"两套校验。
