## 1. ⭐ 四个实战发现（这份清单最值钱的部分）

### 发现 1｜`$readmemh` 不支持 `//` 注释 —— 会**静默失败**

**症状**：LED 乱亮/全亮，但仿真里一切正常。

**原因**：`asm.py` 会把 `;` 注释转成 `// 注释` 写进 `.hex` 文件。

| 环境 | 对 `//` 注释 |
|---|---|
| **Icarus Verilog（仿真）** | ✅ 支持，跳过 |
| **Gowin 综合** | ❌ **不支持**，`$readmemh` 解析失败 |

**失败后的表现链**：
```
readmemh 失败
  → mem 保持 initial 循环填的 8'h00
    → CPU 取指全是 0x00 = OP_NOP
      → pc 一直加，加到 255 回绕，永不 HLT
        → a 保持复位值 0
          → led = 6'b000000
            → LED 低电平点亮 → 全部亮
```

**解法**：综合前把 `.hex` 里的注释行全部删掉（或修 `asm.py`，一劳永逸）。

**验证方法**：看 Gowin 综合日志里有没有 `$readmemh` 相关的 warning。

---

### 发现 2｜**LED 是低电平点亮（active-low）**

| `led[n]` 输出 | 灯 |
|---|---|
| **`0`** | **亮** |
| **`1`** | **灭** |

**怎么发现的**：mem 全 0 时 `a=0` → `led=000000` → 如果高电平点亮应该**全灭**，实际是**全亮** → 只能是低电平点亮。

**注意**：`mul`（a=42=`101010`）在两种极性下都表现为"隔一个亮"，所以**那一次看不出来**；是"全亮"这次才暴露的。

---

### 发现 3｜这块板是 **FT2232 克隆板**，不是 BL702 正品

| 项 | 正品（Sipeed 官方） | 这块板 |
|---|---|---|
| 调试芯片 | **BL702** | **FT2232**（`ftd2xx` 驱动，`USB Serial Converter A/B`、`USB Debugger A/0` 和 `A/1`） |
| SPI Flash | 32Mbit | **`spi flash not found`**（很可能没焊） |
| 主芯片 | GW1NR-9C | ✅ 正品 `GW1NR-LV9 QN88PC6/I5` |

**影响**：
- ✅ Gowin Programmer 用 `ftd2xx` 驱动正常工作
- ⚠️ 按 Sipeed 文档操作时有些步骤对不上（尤其 Flash）
- ⚠️ 开源工具（openFPGALoader 等）可能要指定 FT2232 而非 BL702

**另一个坑**：插上后曾报 `未知 USB 设备(设备描述符请求失败)`，**重新插拔一次就好了**（不是驱动问题，是枚举失败）。

---

### 发现 4｜烧 Flash 要用 **Embedded Flash Mode**，且 `Verify Failed` 是**假警报**

**❌ 错误的做法**（通用教程里写的，对这块板无效）：
```
Access Mode = External Flash Mode
Operation   = eXFlash Erase, Program, Verify
Device      = Generic Flash, Start 0x000000
→ Error: spi flash not found
```

**✅ 正确的做法**：
```
Access Mode = Embedded Flash Mode
Operation   = embFlash Erase, Program, Verify
File        = impl\pnr\cpu_on_fpga.fs
→ 会报 Error: Verify Failed at 0  /  Verify Failed
  但最后一行是 Info: Program Finished!   ← 这才是真的
```

**判定标准：不要看 `Verify Failed`，要做"拔电重插看灯"。**
实测：拔插后用户 LED 仍然显示 `001000`（= 8）→ **写入成功**。

> 多亮的那颗是**板载指示灯**（很可能是 DONE 配置完成灯），与程序无关。
> 读数时把最左边那颗板载灯去掉，剩 6 位才是 `a[5:0]`。

## 2. 实物配置（实际用的值）

### 引脚（`src\top.cst`）

```tcl
IO_LOC  "sys_clk" 52;      IO_PORT "sys_clk"    IO_TYPE=LVCMOS33 PULL_MODE=UP;
IO_LOC  "btn_rst_n" 4;     IO_PORT "btn_rst_n"  PULL_MODE=UP;

IO_LOC  "led[0]" 10;   IO_LOC  "led[1]" 11;   IO_LOC  "led[2]" 13;
IO_LOC  "led[3]" 14;   IO_LOC  "led[4]" 15;   IO_LOC  "led[5]" 16;
（每个 LED 都带 PULL_MODE=UP DRIVE=8）
```

> 引脚号来自官方例程，**没有猜**。

### 工程结构

```
fpga\cpu_on_fpga\
├── src\  cpu.v  top.v  top.cst  top.sdc
├── programs\  prog.hex          ← 综合时被 $readmemh 读取
└── impl\pnr\  cpu_on_fpga.fs    ← 生成的比特流（约 3.4 MB）
```

### 时钟

- `sys_clk` = 27MHz（板上晶振，pin 52）
- `.sdc`：`create_clock -name sys_clk -period 37.037 -waveform {0 18.518} [get_ports {sys_clk}]`
- 不加 `.sdc` 会报 `WARN (TA1132): 'sys_clk' was determined to be a clock but was not created`，且不出 Fmax 报告

### 复位

`cpu.v` 的 `rst` 是**高有效**，按键是低有效，`top.v` 里取反 + 2 拍同步：

```verilog
reg [1:0] rst_sync = 2'b11;
always @(posedge sys_clk)
    rst_sync <= {rst_sync[0], ~btn_rst_n};
wire cpu_rst = rst_sync[1];
```

## 4. 三个官方明写的坑（已验证，都是真的）

| 坑 | 后果 | 做法 |
|---|---|---|
| 没勾 **`Use DONE as regular IO`** | Place&Route 报 **error 2017** | `Project → Configuration → Place&Route → Dual-Purpose Pin` 勾上 |
| 把 `tb/cpu_tb.v` 加进综合源 | 综合器报错或行为异常 | 综合文件列表**只放 `cpu.v` + `top.v`** |
| 用 HDMI 复用的排针 IO | IO 不按预期工作 | 官方警告：HDMI 的 IO 被上拉。本轮没用排针 |

## 6. `top.v` 设计决定（验证是对的）

**不改 `cpu.v`，新写 `top.v` 包住它。**

```
top.v
 ├─ 27MHz sys_clk ─────> cpu.clk
 ├─ btn_rst_n ──取反───> cpu.rst
 └─ cpu.dbg_a[5:0] ───> led[5:0]
```

**理由**：`cpu.v` 是"唯一正确语义"的载体，改它会让仿真和实物变成两份不同的东西。

**结果**：上板全程 `cpu.v` **一行没改**，回去跑 `./run.sh` 三个程序仍全过。

## 8. 本轮明确不做（守纪律）

- ❌ 不焊排针（② 用不到）
- ❌ 不接 RGB 屏（变量太多，第一次上板只允许一个变量：**程序对不对**）
- ❌ 不用 HDMI（那是 ④⑥ 的事）
- ❌ 不买单步时钟按键（`btn_step` + `clk_en` 的方案**没做**，因为不需要——CPU 跑完就停在 HLT，LED 是稳定结果）
- ❌ 不在没验证链路前怀疑自己的 CPU
