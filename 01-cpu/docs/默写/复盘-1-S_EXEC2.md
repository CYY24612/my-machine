## 七个错（按暴露顺序）

| # | 错 | 现象 | 根因 | 正确写法 |
| --- | --- | --- | --- | --- |
| 1 | `pc <= mem[tmp]` 少分号 | 编译报 syntax error | 手误 | 补 `;` |
| 2 | `state <= S_FETCH` 被删 | 所有指令卡在 S_EXEC2，CPU 死 | 状态机漏赋值 → 保持原值 | 放在 `case` 之后 |
| 3 | `OP_LDI` 整个分支缺失 | 执行 LDI 时无匹配，卡住 | 按顺序背，忘了补 | 补回来 |
| 4 | `z <= (a == 0)` | LDA 后 JZ 判断错 | **非阻塞赋值读的是旧值** | `z <= (mem[tmp] == 8'h00)` |
| 5 | ADD/SUB 漏了 z | sum10 / mul 全挂 | 忘了"改 A 就要改 Z" | 补 `z <= ((a ± mem[tmp]) == 8'h00)` |
| 6 | `JZ` 的 else 里 `pc <= pc + 1` | 不跳时**多跳过一条指令** | **多周期 CPU 的 PC 已经加过两次** | 删掉 else，不跳就什么都不做 |
| 7 | `default: ;` 被删 | 非法指令无兜底 | 忽略综合安全 | 加回 `default: ;` |

## 三个真正值钱的认知

### ① `<=` 右边永远是"这一拍之前"的值

```verilog
a <= mem[tmp];
z <= (a == 8'h00);     // ❌ a 还是旧的
z <= (mem[tmp] == 8'h00);  // ✅ 直接对"将来要装进去的值"判断
```

### ② 多周期 CPU 的 PC 语义 ≠ 51

```text
S_FETCH ：pc <= pc + 1     ← 第 1 次
S_EXEC  ：pc <= pc + 1     ← 第 2 次（取操作数）
S_EXEC2 ：pc 已指向下一条 → "不跳"= 什么都不做
```

**51 里"顺序执行"要显式 PC+1，这里加了就错。**

### ③ 状态机里每个分支必须有明确赋值

漏赋值 = 保持原值（仿真卡死）+ 综合推断锁存器（硬件隐患）。

## 默写方法改进

| 问题 | 改进 |
| --- | --- |
| 漏了 LDI | 按**语义分组**背：读(LDA/LDX) 写(STA/STX) 运算(ADD/SUB) 立即数(LDI) 跳转(JMP/JZ/JMPX) |
| 忘记更新 Z | 记口诀：**"改 A 就改 Z"**（LDI/LDA/ADD/SUB/INC/DEC/LDX 都要） |
| JZ 多加 1 | 画一遍三拍的 PC 变化，不要凭 51 的直觉 |
